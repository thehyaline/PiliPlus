## 问题根因

`pubspec.yaml` 第 20 行 `version: 2.1.1.2+5255` 是**四段**版本号（`2.1.1.2`），不符合 pub_semver 要求的三段格式 `主.次.补丁`。该版本号来自上游合并（提交 3da39ec6d "合并上游2.1.1.2版本"）。`lib/scripts/build.ps1` 第 13 行的正则 `^\s*version:\s*([\d\.]+)` 不校验段数，把 `2.1.1.2` 原样保留并拼接 git 提交数（5255）写回 pubspec.yaml。`build_windows.bat` 的安装包步骤（fastforge → pubspec_parse → pub_semver `Version.parse`）严格解析 version 时抛出 `ParsedYamlException: Unsupported value for "version". Could not parse "2.1.1.2+5255".`（flutter build 本身只会警告，不会中断）。

## 修改内容

### 1. 根治：`lib/scripts/build.ps1` 版本号归一化

在提取 `$versionName` 后（第 13-14 行之间），增加 semver 校验：若点分段落超过 3 段，截取前 3 段。

```powershell
if ($line -match '^\s*version:\s*([\d\.]+)') {
    $versionName = $matches[1]
    # pub_semver 只接受 "主.次.补丁" 三段，上游曾用 2.1.1.2 四段版本号，截断为合法 semver
    $segments = $versionName.Split('.')
    if ($segments.Count -gt 3) {
        $versionName = ($segments[0..2] -join '.')
    }
    ...
}
```

这样 `2.1.1.2` → `2.1.1`，写回 pubspec 后为 `2.1.1+5255`；android 分支拼上 commit hash 后也是合法 semver（`2.1.1-xxxxxxxxx+5255`）。以后再次合并上游的四段版本号也不会导致构建失败。

### 2. 修正当前 pubspec.yaml（工作区改动，不提交）

将第 20 行 `version: 2.1.1.2+5255` 改为 `version: 2.1.1+5255`（build 号 5255 保持不变，与 `git rev-list --count HEAD` 一致），使仓库当前状态可被 pub get / IDE / fastforge 等工具正常解析。

## 验证

1. 运行 `powershell -File lib/scripts/build.ps1`（需先临时设置 GITHUB_ENV 指向一个临时文件，因为脚本最后一行会向它写入），确认 pubspec.yaml 版本行被写成 `version: 2.1.1+5255`，且 pili_release.json 中 `pili.name` 为 `2.1.1`。
2. 运行完整 `build_windows.bat`（耗时较长），确认 fastforge 安装包步骤不再报 ParsedYamlException，最终产出 exe 安装包。
