## 问题根因

提交 9169b71b3 把视频播放页布局分支条件从 `!horizontalScreen` 改为 `!horizontalScreen && isPortrait`(lib/pages/video/view.dart:1260)。`horizontalScreen` 在 Windows 上默认 false,导致窗口宽高比跨过 1.0 / 1.2 阈值时,build 每帧在三种完全不同结构的子树(单列 ExtendedNestedScrollView / 左右分栏 / 上视频下三栏)间整体切换,整页反复销毁重建。叠加每帧的:didChangeDependencies 改写 videoHeight → 全页 relayout、RenderVideoHeader 每帧 scrollRatio 通知 → Obx 重建、PLVideoPlayer 每帧新尺寸 → media_kit 纹理重建、onWindowResized 无节流写 Hive、动画期间每帧 refreshPage,UI 线程被占满,表现为拖动窗口时"有概率卡死"。

## 修复内容

### 1. 布局分支切换防抖(核心, lib/pages/video/view.dart)
- 在 `_VideoDetailPageVState` 中新增:
  - `_LayoutMode? _currentLayoutMode` 枚举字段(portrait / landscape / almostSquare / pip),首次 build 直接采用当前尺寸计算的模式,不防抖;
  - `_LayoutMode? _pendingLayoutMode` + `Timer? _layoutSwitchTimer`(150ms);
  - `dispose()` 中取消 Timer(State 目前无 dispose,新增 override)。
- 把 build 中 L1258-1268 的分支判断提取为 `_computeLayoutMode()` 方法。
- build 逻辑:计算目标模式;若与当前模式不同,重置 150ms Timer;Timer 触发时 setState 应用新模式(一次性换树)。防抖期间仍用当前模式构建子树,尺寸字段(maxWidth/maxHeight/videoHeight 等)保持每帧实时更新,播放画面和内容实时跟随窗口。
- 效果:拖动窗口跨阈值时不再每帧换树;停止拖动 150ms 后布局一次性切换。自适应功能完整保留,只是切换延迟 150ms,用户无感。

### 2. onWindowResized / onWindowMoved 写盘防抖( lib/pages/main/view.dart)
- 用 300ms debounce Timer 合并 Hive 写入,连续拖动窗口时只落盘一次,消除每次 WM_SIZE 的平台通道 + 磁盘开销。

## 不动的部分(避免引入功能风险)
- RenderVideoHeader 的 scrollRatio 通知链(已有 toPrecision(2) 守卫、每帧最多一次,是自适应布局固有成本)
- media_kit SimpleVideo 纹理重建(原生依赖行为)
- _setVideoHeight / _animListener 动画状态机(功能核心)

## 验证
- 修改后运行 `flutter analyze` 确认无静态错误。
- 建议用户在 Windows 上反复拖拽窗口跨竖屏/横屏阈值,确认不再卡死、停止后布局正确切换、视频播放与全屏切换功能正常。
