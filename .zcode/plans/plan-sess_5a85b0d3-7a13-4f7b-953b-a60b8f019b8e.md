## 目标
按你确认的方案调整"我的"页布局：板块高度贴合内容（上下对称留白）、板块间用 10px 空白容器、底部避让由外层 ListView padding 单独承担（竖屏 152px / 非底部导航布局 0px）。

所有改动都在 `lib/pages/mine/view.dart`：

## 1. 板块高度改为内容本身（去掉固定 200px 容器）
- `_buildHistoryBody`（525-526 行）：删除包住横向列表的 `SizedBox(height: 200, ...)`，让横向 ListView 按内容自动撑高（卡片约 154px：110 封面 + 8 间距 + 两行文本，随字号自适应）。
- `_buildHistoryBody`（529 行）：内层 ListView padding 由 `.only(left: 20, top: 10, right: 20)` 改为 `.only(left: 20, top: 10, right: 20, bottom: 10)`（上 10 / 下 10 对称，板块下边缘与上边缘留白相等）。
- `_buildFavBody`（611-612 行、615 行）：同样的两处修改。

## 2. 板块间间距容器
- `_buildFav`（557 行 ListTile 之前）：Column 顶部加 `const SizedBox(height: 10)` 作为两板块间的空白间距。放在板块内部顶部（而非 ListView 外层 children 之间），避免历史板块加载隐藏时出现游离空隙；这与旧版 Divider 的位置一致。

## 3. 底部避让 padding 动态化
- 外层 ListView（108 行）：`padding: const .only(bottom: 100)` 改为 `padding: EdgeInsets.only(bottom: avoidBottom ? 152 : 0)`。
- 在 build 开头计算：`final bool avoidBottom = !_mainController.useSideBar && MediaQuery.sizeOf(context).isPortrait;`（与 main/view.dart:88-90 中 `useBottomNav` 的赋值逻辑完全一致）。用 `MediaQuery.sizeOf(context)` 而非直接读 `_mainController.useBottomNav` 是因为 MinePage 在 `NavigationBarType` 里是 const 单例（nav_bar_config.dart:25），主页面重建不会带动它重建；读取 MediaQuery 会注册依赖，窗口旋转/缩放时 MinePage 自动重建，padding 才能跟着切换。
- 需要新增 import：`package:PiliPlus/utils/extension/size_ext.dart`（`isPortrait` 扩展所在，view.dart 目前未导入）。
- 152 的来历：原 100（导航栏避让）+ 2 × (200 − 174)（两个板块各缩减约 26px），加到 padding 上，保持页面总滚动长度与现在一致。非底部导航布局（侧边栏/宽屏/横屏）时 padding 为 0，不做避让。

## 4. 预期效果
- 观看记录卡片 → "我的收藏"标题：约 36px → 20px（板块自身 10px 底部 + 10px 间距容器）。
- 收藏卡片 → 页面底部（竖屏全滚到底）：间距区域变为 10px + 152px 避让区，其中避让区大部分被导航栏浮层（约 72px）遮挡，可见空白约 90px（现在约 64px）——总滚动长度不变，这是"缩减值加回 padding"的直接结果。
- 侧边栏/宽屏布局：底部 100px 固定空白消失，页面不再有过多底部留白。

## 5. 验证
- 运行 `flutter analyze` 确认无告警。
- 说明：若去掉 SizedBox 后横向 ListView 高度行为异常（正常情况下会按最大子项高度撑开），退化为显式 `SizedBox(height: 174)` 方案。
- 视觉确认需你本地运行查看（竖屏手机页 + 宽屏窗口各看一眼）。
