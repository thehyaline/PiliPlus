## 修复搜索页三处问题

### 1. 平板布局下侧栏搜索入口不显示默认词

根因：默认词通过路由参数 `hintText` 传入搜索页（`SSearchController.onInit` 读取 `Get.parameters['hintText']`），而 `main/view.dart:584` 侧栏搜索按钮和 `mine/view.dart:204` 搜索按钮都是裸调用 `Get.toNamed('/search')`，没带参数。

修改：
- `lib/pages/home/controller.dart`：在 `HomeController` 上新增 getter
  ```dart
  Map<String, String>? get searchParams =>
      enableSearchWord && defaultSearch.value.isNotEmpty
          ? {'hintText': defaultSearch.value}
          : null;
  ```
  （比首页现有写法多一个 `isNotEmpty` 判断：默认词还没请求回来时退回显示"搜索"占位，而不是空占位）
- `lib/pages/main/view.dart`（`userAndSearchVertical` 的搜索按钮，同时覆盖 NavigationDrawer / NavigationRail / 窄侧栏三处）：改为 `Get.toNamed('/search', parameters: _mainController.homeController.searchParams)`
- `lib/pages/mine/view.dart:204`（无首页 tab 时的搜索按钮）：同样处理
- `lib/pages/home/view.dart:160-165`：首页入口改用 `_homeController.searchParams`，三处入口行为统一

### 2. 输入为空时不显示清空按钮

`lib/pages/search/view.dart:148-153`：把清空 IconButton 包进 `ValueListenableBuilder<TextEditingValue>`（监听 `_searchController.controller`），仅当 `value.text.isNotEmpty` 时渲染，否则渲染 `SizedBox.shrink()`。用 ValueListenableBuilder 而不是 Obx，是因为 TextEditingController 本身是 ValueNotifier，任何路径（键盘输入、路由带 `text` 参数、点击热词、清空）下文本变化都能自动触发，不会漏状态。清空按钮隐藏后 TextField 是 Expanded，会自动吸收空出的宽度，布局不会跳动。`onClear()` 中"空文本时 Get.back()"的分支保留（无副作用，成为死代码无妨）。

### 3. 手机布局下搜索框占满宽 + 结果页伪输入框同样适配 + 平滑过渡

- 新建 `lib/common/widgets/search_bar_width.dart`：共享的 `SearchBarWidth` 组件（两个页面复用同一套宽度逻辑）：
  ```dart
  // isPortrait=true（即搜索页下方模块纵向堆叠时，与用户给的标准一致）：目标宽度 = 可用宽度（占满）
  // isPortrait=false：目标宽度 = min(可用宽度, 500)（保持现有居中限宽）
  // 用 LayoutBuilder 取 AppBar title 槽的可用宽度；
  // 用 TweenAnimationBuilder<double>（250ms，easeInOutCubicEmphasized，与首页顶栏动画风格一致）
  // 包裹 ConstrainedBox(minWidth: 200, maxWidth: 目标宽度)，断点切换时宽度平滑过渡而不是瞬跳
  ```
- `lib/pages/search/view.dart`：AppBar title 里的 `Center(ConstrainedBox(...))` 改为 `Center(SearchBarWidth(isPortrait: isPortrait, child: SizedBox(height: 44, child: Material(...))))`，`isPortrait` 用现有 state 缓存值
- `lib/pages/search_result/view.dart`：同样替换，`isPortrait` 在 build 里取 `MediaQuery.sizeOf(context).isPortrait`

关于"拉伸窗口时变化突然"的解决办法：宽度不做硬切换，而是做成目标值的隐式动画——拖拽窗口连续变化时宽度实时跟随（动画不断重定向，只有轻微滞后），跨越横竖屏断点时 250ms 内平滑地从 500 渐变到全宽（或反向），不会有跳变。注意：搜索页下方模块的纵向/左右排布切换是 Sliver 结构重组，无法低成本做过渡动画，保持现状瞬切，本次只平滑搜索框宽度（这也是用户诉求的落点）。

### 影响面
只改搜索相关页面和两个入口，不触碰其他页面。手机竖屏下（可用宽度 < 500）行为与现在完全一致，无回归风险；变化只出现在竖屏且可用宽度 > 500（平板竖屏、窄高窗口）时搜索框从 500 限宽变为占满，以及断点处的平滑过渡。
