## 幽灵悬浮高亮 — 根因与修复方案

### 根因分析

所有悬停高亮（框架 InkWell/Material 默认 hover 底色、直播间 Tab 的 overlayColor、ListTile 等）都由 `MouseTracker` 驱动。`MouseTracker` 每帧在"设备最后已知位置"重新命中测试并维持高亮（`updateAllDevices`，mouse_tracker.dart:366）。当某个鼠标/触控笔设备的最后位置不再更新（窗口隐藏到托盘、最小化、被遮挡时鼠标在窗内；触控笔悬停残留；或存在第二个鼠标类设备）时，高亮就被每帧无限确认——**鼠标怎么移动都不会消失**，与你的现象完全吻合。

已排除：表情预览浮层（你看到的是底色高亮而非小浮层）、播放器控制条（有定时器兜底）、windows/runner 改动（今日 DPI/窗口改动不涉及鼠标消息，已验证与鼠标跟踪无关）。

### 修复方案

**核心：全局指针设备复位**（一次性治好所有框架高亮 + 自研 hover 状态）

1. `lib/common/widgets/scale_app.dart`：在 `_handlePointerDataPacket` 中 peek 原始 `PointerData`，记录所有见过的鼠标/触控笔（`kind == mouse || stylus`）设备 id 集合（存到 binding 实例上）。
2. 新增 `lib/common/widgets/hover_reset.dart`：
   - `resetHover()`：对每个已记录的设备 id，通过 microtask（避免事件分发重入）派发合成 `PointerRemovedEvent(device: id, kind: mouse)`。`MouseTracker.updateWithEvent` 会清空该设备状态并派发全部 exit（mouse_tracker.dart:317-339）→ 所有悬停高亮/浮层统一复位；真实设备的下一个事件会自动重新注册跟踪，不影响后续使用。
   - 触发时机：
     - `AppLifecycleListener`/`WidgetsBindingObserver`：`inactive`/`hidden`/`paused`/`resumed` 时复位（覆盖最小化、托盘隐藏、窗口遮挡、切窗、Android 退后台/返回前台）。
     - main.dart 根部（BackDetector 旁）包一层 `MouseRegion(onExit: resetHover)`，兜底鼠标离开窗口及多设备残留场景。
3. main.dart：注册上述 observer + 根部 MouseRegion（Android 端无鼠标时自动跳过，无副作用）。

**次要：Android 表情预览无法收起**（custom_tooltip.dart:120 目前只能点浮层本身关闭）

- `CustomTooltip` 增加可选面板级 `ValueNotifier` 分组：同一表情面板同时只显示一个预览，长按新表情时旧预览自动收起。
- 表情面板根部加 `Listener(onPointerDown)`：点任意位置收起当前预览。
- 桌面端 enter/exit 逻辑不变，由全局复位兜底。

### 验证

- `flutter analyze` 通过。
- Windows 手动验证：悬停任意卡片 → 最小化 / Alt-Tab / 隐藏到托盘 → 恢复后高亮消失；鼠标移出窗口后高亮消失；正常使用（移动鼠标、点击）高亮行为不受影响。
- Android 手动验证：长按表情出预览 → 点其它位置即收起；退后台再返回无残留高亮。
- 若仍可复现：在 `resetHover()` 中临时打印设备 id 列表定位具体设备（作为排查手段，不作为交付内容）。
